04

Arquitectura de mínimo precio & las 3 palancas

Cumplir el 100% al literal, sin sobre-diseñar un solo peso.

Palanca 01 · mayor impacto

El DRP se arma con el hardware que la SEP ya tiene

SPARC T8-4, HPE SDFlex/Alletra/StoreOnce, Power E950, F5, Imperva, Fortinet, Aruba y CommVault son de la SEP. El licitante no compra cómputo, almacenamiento, red ni seguridad para el DRP: solo mudanza, reactivación, antiransomware, monitoreo, respaldo y enlaces. Diferencia de precio decisiva frente a quien cotice un DRP nuevo.

Palanca 02 · confirmar en junta

Los motores de base de datos los licencia la SEP

El pliego indica que la SEP provee las licencias de Oracle EE/RAC, SQL Server e Informix — el rubro más caro — en ambas sedes. Si se confirma, tu costo de licencia se reduce a SO + VMware + seguridad + herramientas.

Palanca 03 · el mayor amplificador

Descifrar la regla 40/60

“Recursos SEP = 40% del total, 60% para crecimiento” puede significar comprar ~2.5× la capacidad real. Aclarar si es capacidad instalada o escalable puede recortar millones de pesos del sitio Principal.

06

Preguntas críticas para la junta de aclaraciones

No es un trámite: cada respuesta mueve el precio o evita una descalificación.

  1. Regla 40/60: ¿capacidad instalada 2.5× o capacidad escalable a +60% sin cambiar hardware? — impacto máximo
  2. Licencias de motores de BD: confirmar que la SEP aporta Oracle EE/RAC, SQL Server e Informix en ambas sedes.
  3. Marca de seguridad en el Principal: ¿se aceptan las mismas familias que la SEP ya posee en DRP (F5 + Imperva + Fortinet) en vez de Palo Alto/Infoblox?
  4. SPARC “nuevo ≤2 años”: ¿se acepta Fujitsu SPARC M12 o equivalencia con soporte Oracle Premier? Si no, es riesgo de descalificación para todos.
  5. Inventario: cifra oficial de BD (1,008 vs 1,018), unidades de RAM (MB vs GB) y tamaños anómalos (MariaDB >1 PB) para dimensionar sin sobre/sub-cotizar.
  6. Commvault: ¿obligatorio para recuperar respaldos históricos? El DRP ya usa CommVault → estandarizar evita incompatibilidad.
  7. SQL Server 2012 (EOL) y 2017 Developer en producción: ¿ESU y regularización de licencia a cargo de quién? Riesgo legal e ISO 27001.
